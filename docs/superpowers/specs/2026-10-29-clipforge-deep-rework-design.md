# ClipForge: дизайн глубокой переработки

## 1. Цель

Превратить текущий Clipdeck в самостоятельный продукт под рабочим названием **ClipForge**: с собственной визуальной системой, языком интерфейса, структурой приложения, документацией и внутренними именами. TikTok-публикация, статистика и локальное хранение данных должны остаться рабочими.

Это не попытка скрыть происхождение исходников. Проект будет оформлен как существенно переработанный open-source форк с сохранением обязательной информации об исходных компонентах и их лицензиях.

## 2. Пользователь и результат

Продукт рассчитан на владельца нескольких собственных TikTok-аккаунтов, которому нужно:

- хранить аккаунты локально;
- публиковать видео по выбранным группам;
- видеть результат каждой попытки;
- наблюдать статистику роликов и аккаунтов;
- понимать состояние окружения без ручного поиска ошибок.

Признак успеха: новый пользователь видит цельный продукт ClipForge, а не набор экранов Clipdeck, при этом существующие рабочие сценарии проходят регрессионные проверки.

## 3. Цели

- Заменить бренд Clipdeck в пользовательском интерфейсе, README, имени сборки, диагностике и скриншотах.
- Сделать единую навигационную модель: обзор, публикации, аккаунты, статистика, настройки.
- Ввести единый слой application services между UI, БД и TikTok-адаптером.
- Перенести UI-строки, названия ролей и настройки в собственный словарь приложения.
- Обновить визуальную систему: палитра, типографика, sidebar, карточки состояния, таблицы, пустые состояния и ошибки.
- Переработать внутренние названия новых/изменяемых классов и модулей без рискованного массового переименования внешней TikTok-библиотеки.
- Обновить документацию, запуск, сборку, self-test и тестовые сценарии.
- Сохранить лицензию проекта и атрибуцию `TikTokAutoUploader`/`tiktok-signature`.

## 4. Не входит в работу

- Обход блокировок TikTok, автоматизация чужих аккаунтов или скрытие происхождения кода.
- Переход на официальный TikTok API без отдельной спецификации и ключей.
- Облачная синхронизация, серверная авторизация и публикация данных в интернет.
- Удаление LICENSE, copyright-уведомлений или списка сторонних компонентов.
- Полная перепись механизма подписи запросов и браузерной автоматизации, если текущий адаптер продолжает работать.

## 5. Подходы

### A. Быстрый ребрендинг

Только название, цвета, README и тексты. Минимальный риск, но код и интерфейс будут явно похожи на исходный продукт.

### B. Глубокая переработка — выбранный подход

Сохраняется проверенный TikTok-адаптер, а приложение получает новый бренд, UI, navigation shell, application services, словарь строк, структуру настроек и документацию. Риск ниже, чем у полного переписывания, а визуальная и продуктовая самостоятельность значительно выше.

### C. Реализация с нуля

Текущий код используется только как прототип поведения. Максимальная самостоятельность, но высокая вероятность регрессий в логине, cookies, публикации, статистике и сборке.

Выбран B: он даёт существенную самостоятельность продукта без повторного изобретения нестабильной интеграции TikTok.

## 6. Целевая структура

- `src/app/` — application services, use cases, состояния и доменные DTO приложения.
- `src/core/` — пути, БД, cookies, импорт и хранилище статистики; существующие компоненты будут постепенно адаптированы через совместимые фасады.
- `src/ui/` — новый shell, sidebar, страницы, диалоги и визуальные компоненты.
- `tiktok_uploader/` — изолированный внешний адаптер; изменения только для совместимости, устойчивости и явной маркировки интеграционного слоя.
- `docs/` — архитектура, запуск, релиз, сторонние компоненты и решения по бренду.
- `tests/` — unit, smoke и UI-сценарии для новых сервисов и ключевых экранов.

Переименование будет поэтапным: сначала публичные точки входа и UI, затем внутренние модули с совместимыми импортами. Это уменьшает риск сломать сборку и старые тесты.

## 7. Брендинг и UI

Рабочее имя: **ClipForge**. Оно означает инструмент, который превращает исходное видео в серию публикаций.

Предлагаемое направление:

- тёмная графитовая основа;
- акцент electric violet/amber для действий и статусов;
- компактный левый sidebar вместо ощущения «набора вкладок»;
- обзор с карточками: аккаунты, очередь, успешные публикации, ошибки;
- публикация как пошаговый рабочий экран;
- единые компоненты статусов, пустых состояний, предупреждений и подтверждений;
- русский интерфейс сохраняется, технические сообщения и README становятся единообразными.

Логотип и иконка будут простыми и локальными, без копирования исходной айдентики.

## 8. Совместимость и миграция

- Существующая SQLite-база и cookies не удаляются.
- Новые ключи настроек получают миграцию с чтением старых значений.
- Старые команды self-test и запуск из исходников продолжают работать либо получают явные совместимые алиасы.
- Путь данных остаётся локальным, чтобы пользователь не потерял аккаунты, журнал или статистику.
- Релизная сборка получает новое имя, но не меняет расположение пользовательских данных без мигратора.

## 9. Этапы реализации

1. Зафиксировать бренд, словарь терминов и карту текущих экранов.
2. Ввести application shell и слой сервисов с тестами.
3. Переработать тему, sidebar и общий набор компонентов.
4. Перепроектировать обзор и страницы публикаций/аккаунтов.
5. Перепроектировать статистику, настройки и диагностику.
6. Обновить dialogs, тексты ошибок, README, LICENSE-notice и сборку.
7. Выполнить миграционные, unit, smoke, UI и compile-проверки.
8. Сделать финальный аудит упоминаний старого бренда и проверку чистого checkout.

## 10. Критерии готовности

- В пользовательском интерфейсе, имени exe, README и self-test используется новый бренд.
- Поиск по проекту не оставляет случайных пользовательских упоминаний старого продукта; историческая атрибуция остаётся только в разделе сторонних компонентов/лицензии.
- `pytest tests -q`, `compileall`, GUI smoke и screenshot-проверки проходят.
- База, cookies, импорт аккаунтов, публикация, retry, история, CSV и статистика не регрессируют.
- README описывает продукт как существенно переработанный форк и содержит корректную атрибуцию.
- Реальный TikTok upload/login помечен как требующий пользовательских аккаунтов и не считается локально проверенным.

## 11. Решения, оставленные строителю

- Рабочее имя ClipForge использовать как default, если до реализации не задано другое.
- Сохранить Python/PyQt6/SQLite и текущую зависимость от TikTok-адаптера.
- Не добавлять сетевые сервисы и новые обязательные зависимости без необходимости.
- Делать изменения небольшими коммитами с проверками после каждого слоя.
